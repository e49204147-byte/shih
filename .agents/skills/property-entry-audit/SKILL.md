# 基金工程財產登帳全卷審核與模擬會辦把關（Skill 2：`property-entry-audit`）

## 給人看的導讀

人類導讀手冊與總流程圖放在 Obsidian：`C:\2026aiagents\公務類指令\00_財產登帳雙Skill導讀與標準作業總流程圖.md`（AI 執行本技能時不必讀）。本檔 `SKILL.md` 為唯一正本，Obsidian 只放連結。

本技能是公文送出線上系統前的**「模擬會辦與長官審核守門員」**，同時可用於**既有／歷史案件的獨立盲測覆盤**。
為兼顧**「每個審核角色職責單一純粹（不混亂失焦）」**與**「未來可無限橫向擴充不同主管／會辦單位視角」**，本技能採用**「1 個總調度入口 ＋ N 個單一職責角色模組（`references/role-*.md`）」**設計：
- 每個角色模組只專注審查自己職掌的業務紅線（每個主管腦袋越單一越精準）。
- 使用者可要求**「全卷三關聯審（預設）」**，也可指定**「單一角色專審（如：只用主計室視角審）」**。
- 未來若要新增其他主管（如：技正、局本部各組、或特定長官個人看稿偏好），只需在 `references/` 新增獨立的 `role-xxx.md` 模組，完全不影響既有角色。

---

## 一、 審核入口與兩種執行模式

先告知正在使用 `property-entry-audit`。讀取時同樣採 **PDF 雙軌分流機制**（原生文字型 PDF 如線上簽稿、財產單直接提取文字；掃描影像型 PDF 如驗收單、決算書、撥款表調用 OCR 或讀取 `00_案件簽辦與審核總表.md` 已轉存之結構化表格與原檔核對）。

1. **【模式 A：Skill 1 產出後之送簽前自我把關】**
   - 直接讀取案件整理夾內的 `00_案件簽辦與審核總表.md`、正式簽稿、系統匯出之財產單 PDF、未完工程 Excel 及 `附件N_...對照圖.jpg`，做上線前的最後一哩路驗算。
2. **【模式 B：既有簽稿／同仁案件／歷史卷宗之獨立盲測】**
   - 當使用者丟入已寫好簽稿的案件資料夾時，**不預設原簽結論正確**，直接拿原始工程結算驗收證明書、決算書、未完工程明細表與財產單 PDF 重新做交叉比對，抓出退件地雷。

## 二、 依序調用「三大單一職責角色模組」（預設全開，亦可指定單一視角）

執行審核時，請主動讀取（`read_file`）`references/` 下對應的單一職責角色規範，逐關獨立審查（不把不同處室邏輯混成一團）：

1. **【第一關：主計室專責視角】** → 必讀 [references/role-accounting.md](references/role-accounting.md)
   - **單一核心職責**：只審**「錢與帳」**——驗收證明書結算總價 vs. 基金申請入帳總額之差額交代（營業基金自籌、工管費、空污費、技服費分攤）、未完工程 Excel 逐碼沖銷算術（`項次`、`A0KHH...` 代號、`總撥付 − 已沖轉 ＝ 帳列餘額`），以及**沖銷後餘額去向**（1元營業稅尾差、小額節餘款繳回、或與他案共用預算代號尚在履約中留待結案）。
2. **【第二關：秘書室（財產管理）專責視角】** → 必讀 [references/role-secretariat.md](references/role-secretariat.md)
   - **單一核心職責**：只審**「財產單與產籍規則」**——財產單 PDF 算術防呆（`原價 ± 本次增減 ＝ 新價`，抓加減方向打反或尾數誤植）、`購置／驗收日期` 與驗收合格日一致性、同財編跨多批驗收之簽文括號分列備註、`型式／廠牌欄` 基金代號完整性、財物標準分類／年限／殘值、土地地質改良「先增後減」同額配對，以及事故災損／汰換舊品依《審計法》第 58 條另案報損減帳交代。
3. **【第三關：科長／主任（業務主管）核稿專責視角】** → 必讀 [references/role-supervisor.md](references/role-supervisor.md)
   - **單一核心職責**：只審**「業務定性、公文邏輯、圖文一致性與跨案追蹤」**——《國際（內）商港建設經費負擔原則》公共基礎設施定性、往返公文脈絡完整性、**範本複製貼上殘留字抓蟲（Copy-Paste 污染）**、個人公文寫作偏好（國字億萬單位、附件1~N首次出場順序、分割檔寫法）、**「簽文 vs. 三欄對照圖 `.jpg` vs. 財產單 PDF」三方視覺鏡像核對**。
   - **對照圖結構檢查**：依 Skill 1 的 `../property-entry-memo/references/diagram-spec.md` 檢查三欄是否為「左對帳／中依據／右入帳」、卡對卡箭頭與一對一對齊、總勾稽式、國字億萬、無工作備註雜訊；不符者列 🟡 黃燈（數字錯誤則 🔴 紅燈）。
4. **【未來擴充插槽】**：若 `references/` 下有新增其他角色模組（如 `role-chief-engineer.md` 等），依使用者指示或案型自動加掛審查。

## 三、 固定輸出結構（審核報告五大區塊）

每次執行 `property-entry-audit`，必須依序輸出以下 **5 個區塊**：

### 1. 【總體審核燈號判定（🔴紅燈 ／ 🟡黃燈 ／ 🟢綠燈）】
- 🔴 **紅燈（必退件硬傷，嚴禁直接送簽）**：如金額算術不合、驗收總價與入帳額差額未交代、未完工程餘額不足或巨額餘額未說明去向、財產單加減打反或數字誤植、跨案範本文字殘留、簽文與 `.jpg` 對照圖數字或附件號不一致。
- 🟡 **黃燈（建議補強說明，避免會辦被問）**：如跨兩筆基金代號於財產單型式欄漏填一碼、同財編多批驗收未於簽文括號註明各批驗收日、保管人非本人尚未提示內會等。
- 🟢 **綠燈（全卷 100% 勾稽通過，可立即上線送簽）**。

### 2. 【三關分角審查明細表（主計室 ／ 秘書室財管 ／ 科長主任）】
以表格清楚列出每個角色模組檢查的每一個子項、`通過 ✅ / 警告 🟡 / 退件 🔴`、具體核對數據（含頁碼／儲存格依據）及問題說明。

### 3. 【一鍵修復：紅字局部替換修正包（$\textcolor{red}{\textbf{紅字}}$）】
- 若有任何 🔴紅燈 或 🟡黃燈 需修改簽文或對照圖文字：
  - **嚴守「紅字局部替換原則」**：原簽沒問題的段落與文字**一字不動**，只列出需替換的段落，並將修改或新增的文字以 **$\textcolor{red}{\textbf{紅字}}$** 標示，讓承辦人可直接複製貼上。
  - 若 `.jpg` 對照圖有誤，同步更新 `00_案件簽辦與審核總表.md` 的三欄文字並重新產出 `.jpg`。

### 4. 【線上公文系統「送簽前操作檢查表（Pre-Flight Check）」】
提醒公文內文以外的系統設定：
1. **【內會保管人檢查】**：列出財產單上的「保管人」姓名；若非承辦人本人，提醒：**「⚠️ 線上公文流程務必先加設【內會：保管人】」**。
2. **【標準會辦順序確認】**：`內會保管人（若非本人） → 會辦秘書室（財管） → 會辦主計室 → 陳核科長／主任`。
3. **【母文與唯一併陳收文號檢查】**：確認文中寫 `（詳來文）` 之母文號，以及寫 `（詳併陳案件）` 之唯一前案確有本局總收文號，其餘公文皆已排入 `附件1` 起。

### 5. 【下集預告：後續未結案追蹤備忘錄（Follow-up Tracker）】
自動盤點本案簽准後還需要持續追蹤的事項（若無則標示「本案全數完結，無後續待辦」）：
- **尚待港務公司補報之同案核准項目**（例如：會議核准 3 項，本次僅報 2 項，尚有「○○工程」待港務公司送件）。
- **共用基金代號未完工程尾款追蹤**（例如：代號 `A0KHH...` 沖銷後尚餘 X 元，待同代號他案「○○工程」完工決算時一併沖銷／繳回）。
- **舊品另案報審計部減帳追蹤**（例如：災損修復案之舊品折舊淨值 X 元，待依《審計法》第 58 條另案報審計部核准後辦理財產減損）。
