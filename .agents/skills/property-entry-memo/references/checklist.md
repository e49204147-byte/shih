# 盤點：PDF 雙軌讀取與應備文件清單（第一階段第 1 步）

列每份可讀檔案、PDF 頁數與檔案大小（MB）、Excel 工作表、版本與未讀原因。**10 MB 上限檢查**：若發現原始來文 PDF 超過 10 MB（例如掃描版決算書、驗收證明書或幾十頁點交位置圖冊），先於第一階段回覆清單提醒承辦人是否要呼叫 `pdf24-official-pdf` 壓縮或拆分（先確定分卷數，再進第二階段編 `附件01~N` 與寫簽，避免寫完才重編；未經確認不主動操作 PDF24）。先按應備文件清單逐項核對，再按案型檢視內容；財產單尚未製作時屬後續文件，不列為當下缺件。逐頁檢視影響結論的 PDF；圖面與照片看影像；Excel 看欄名、實際儲存格、公式及快取值。

**PDF 檔案雙軌分流讀取機制（自動判別文字層 vs. 掃描影像，支援本機 PDF24 與 Python 工具）**
- **第一軌：原生文字型 PDF（如：線上公文簽稿、電子來函、國有財產增加／增減值單 PDF、電腦匯出之分帳表）→ 直接調用 PDF 轉文字工具**
  - 先檢測 PDF 是否具有內嵌文字層；若有文字層（如公文主旨說明、文號、財產單欄位），優先調用**直接轉文字工具**（Python `PyMuPDF (fitz)` / `pypdf` 抽取文字，或調用本機 `C:\Program Files\PDF24\pdf24-DocTool.exe`），秒級零誤差取出完整文字，不走影像 OCR 以免耗時或產生字元誤判。
- **第二軌：掃描影像型 PDF（如：用印掃描之工程決算書、工程結算驗收證明書、工程結算明細表、代辦工程經費請撥款情形表、現場點交紀錄）→ 自動調用 OCR**
  - 當檢測發現 PDF 無內嵌文字層（或文字極少、屬掃描圖片頁面）時，立即調用 **OCR 流程**（可調用本機 `C:\Program Files\PDF24\pdf24-Ocr.exe` 轉為可搜尋文字 PDF，或以 `PyMuPDF (fitz)` 將頁面渲染為高解析度 PNG 圖檔後結合 AI 視覺多模態 OCR 逐欄辨識），主動將工程決算明細、驗收合格日期、撥付沖銷數字與點交內容擷取並整理為結構化 Markdown 表格。

**應備文件正面表列檢核表（Checklist）**
- **外部來文基本必備（每案必檢）**：(1) 正式來函（含發文日期、字號、本局總收文號）；(2) 工程決算書（含委託技服決算書，若有分攤）；(3) 工程結算驗收證明書，核對實際竣工日與**驗收合格日（折舊起算依據）**；(4) 經費撥付及沖銷明細表（預算科目明細表），須含未完工程項次與基金代碼（`A0KHH...`）；(5) 竣工位置圖及施工／點交照片。
- **本局內部對帳必備（每案必檢）**：(6) 本局最新《未完工程明細表 Excel》；(7) 本局財產明細清冊 CSV 或既有財產卡；(8) 承辦依建議製單後匯出的財產增加／增減值單 PDF。第 (8) 項在第一階段一律標「❌ 待製單後提供（非當下缺件）」。
- **特殊案型加附（先判適用，再檢核）**：(A) 分批投入案（如消波塊）：各批後續工程驗收證明與數量分攤表；(B) 爭議報支或往返釐清案（如 S1~S3 櫃場、CCTV 案）：經費支應原則會議紀錄、往返確認函、款源分攤表及前案核定簽函；(C) 事故災損修復案（如過港隧道風機）：同意基金勻支函、現地點交紀錄及舊財產減值折舊分析表（供另案依《審計法》第 58 條報損減帳）。不適用者註明「不適用」，不作缺件。
